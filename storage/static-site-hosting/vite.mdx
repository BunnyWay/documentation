Vite builds to a folder of static files, which is exactly what Bunny Storage serves. This page covers the Vite-specific parts. The deployment mechanics live in the [Bunny CLI](/storage/static-site-hosting/bunny-cli) and [manual setup](/storage/static-site-hosting/manual-setup) guides.

## Build

```bash
npm run build
```

Vite writes to `dist` by default. If you changed `build.outDir` in `vite.config.js`, deploy that folder instead.

Check the build locally before you deploy it:

```bash
npm run preview
```

## Deploy

<Tabs>
  <Tab title="Bunny CLI">
    ```bash
    bunny sites create my-vite-site
    bunny sites deploy ./dist --build "npm run build" --production
    ```

    The CLI creates the Storage Zone and Pull Zone, uploads `dist`, and prints the live URL. See the [Bunny CLI guide](/storage/static-site-hosting/bunny-cli) for previews, rollbacks, and GitHub Actions.

  </Tab>
  <Tab title="Manual">
    Create a Storage Zone, upload the contents of `dist` to its root, and connect a Pull Zone. See [Manual setup](/storage/static-site-hosting/manual-setup) for the full walkthrough.
  </Tab>
</Tabs>

## Serve from a subpath

Vite assumes your site is served from the domain root. If you deploy into a subfolder of a Storage Zone, set `base` so asset URLs resolve:

```js vite.config.js
export default defineConfig({
  base: "/docs/",
});
```

Leave `base` alone when the site is served from the root, which is the case for a Pull Zone hostname and for `bunny sites`.

## Environment variables

Vite embeds variables prefixed with `VITE_` at build time:

```bash .env.production
VITE_API_URL=https://api.example.com
```

```js
const apiUrl = import.meta.env.VITE_API_URL;
```

Because the values are baked into the bundle, changing one means a rebuild and a redeploy. Never put a secret in a `VITE_` variable, since anything in the bundle is public.

To override a value for a single deploy:

```bash
bunny sites deploy ./dist --build --env VITE_API_URL=https://staging.example.com
```

## Client-side routing

A Vite site with React Router, Vue Router in history mode, or any other client-side router needs missing paths to serve `index.html`. Configure the 404 fallback on the Storage Zone, as described in [client-side routing](/storage/static-site-hosting/manual-setup#configure-client-side-routing).

Multi-page Vite builds, and static site generators built on Vite such as Astro and VitePress, produce a file per route and need no fallback.

## Caching

Vite adds a content hash to built asset filenames, such as `main.a1b2c3.js`, so those files can cache for a year. Keep `index.html` on a short cache time, because it's the file that points at each new build's assets. See [cache configuration](/storage/static-site-hosting#cache-configuration).
