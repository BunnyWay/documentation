Vue apps built with Vite, Vue CLI, or Nuxt all produce static files that Bunny Storage can serve. This page covers the Vue-specific parts. The deployment mechanics live in the [Bunny CLI](/storage/static-site-hosting/bunny-cli) and [manual setup](/storage/static-site-hosting/manual-setup) guides.

## Build

<Tabs>
  <Tab title="Vite (Vue 3)">
    ```bash
    npm run build
    ```

    Output: `dist`

  </Tab>
  <Tab title="Vue CLI">
    ```bash
    npm run build
    ```

    Output: `dist`

  </Tab>
  <Tab title="Nuxt (static)">
    ```bash
    npm run generate
    ```

    Output: `.output/public`

  </Tab>
</Tabs>

## Deploy

<Tabs>
  <Tab title="Bunny CLI">
    ```bash
    bunny sites create my-vue-app
    bunny sites deploy ./dist --build "npm run build" --production
    ```

    For Nuxt, deploy `.output/public` and build with `npm run generate`. See the [Bunny CLI guide](/storage/static-site-hosting/bunny-cli) for previews, rollbacks, and GitHub Actions.

  </Tab>
  <Tab title="Manual">
    Create a Storage Zone, upload the contents of your build folder to its root, and connect a Pull Zone. See [Manual setup](/storage/static-site-hosting/manual-setup) for the full walkthrough.
  </Tab>
</Tabs>

## Vue Router history mode

In history mode, Vue Router produces clean URLs like `/about` with no hash. The first request for one goes to the CDN, and nothing is stored at that path, so it returns a 404 unless you add a fallback.

Set the Storage Zone's **404 File path** to `/index.html` and enable **Rewrite 404 to 200 status code**, as described in [client-side routing](/storage/static-site-hosting/manual-setup#configure-client-side-routing).

<Warning>
  Without this, refreshing on `/about` or opening a shared link to
  `/products/123` returns a 404.
</Warning>

Hash mode (`createWebHashHistory`) keeps the route after a `#`, so every request hits `index.html` and no fallback is needed. Clean URLs are better for SEO and sharing, so prefer history mode with the fallback configured.

`nuxt generate` pre-renders an HTML file per route, so a Nuxt static site needs the fallback only for routes it can't discover, such as dynamic ones.

## Environment variables

<Tabs>
  <Tab title="Vite">
    ```bash .env.production
    VITE_API_URL=https://api.example.com
    ```

    ```js
    const apiUrl = import.meta.env.VITE_API_URL;
    ```

  </Tab>
  <Tab title="Vue CLI">
    ```bash .env.production
    VUE_APP_API_URL=https://api.example.com
    ```

    ```js
    const apiUrl = process.env.VUE_APP_API_URL;
    ```

  </Tab>
  <Tab title="Nuxt">
    ```ts nuxt.config.ts
    export default defineNuxtConfig({
      runtimeConfig: {
        public: {
          apiUrl: process.env.API_URL,
        },
      },
    });
    ```

  </Tab>
</Tabs>

Values are embedded at build time, so they're public and they only change when you rebuild. Keep secrets on a server, or in an [Edge Script](/scripting).

## Caching

Vue builds hash asset filenames, such as `main.a1b2c3.js`, so those files can cache for a year. Keep `index.html` on a short cache time, because it's the file that points at each new build's assets. See [cache configuration](/storage/static-site-hosting#cache-configuration).
