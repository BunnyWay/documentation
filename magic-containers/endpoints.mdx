Once you have a [deployed container](/magic-containers/quickstart), you can expose it to the internet using two endpoint types: **CDN** for HTTP(S) traffic or **Anycast** for direct IP access.

## CDN

CDN endpoints route HTTP(S) traffic through bunny.net's edge network, improving performance and reducing latency based on user location.

<Info>
  For more information about CDN, see our [CDN
  documentation](https://bunny.net/academy/cdn/what-is-a-cdn-content-delivery-network/).
</Info>

To create a CDN endpoint:

1. Go to **Magic Containers** and select your container.

2. Click **Endpoints**, then **Add New Endpoint**.

<Frame>
  ![](/images/docs/1ef14f4c14be1d252dfecd23dac3a6d6d81394af6f5ee821323f7c8e78203ad2-image.png)
</Frame>

3. Select **CDN** as the type.

<Frame>
  ![](/images/docs/f0373c65fac9c4ee93c2a5bc2450ab4e31b921e1f89317d7d782099918044a65-image.png)
</Frame>

4. Configure the endpoint:
   - **Name**: A unique name for this endpoint.
   - **Container Port**: The port your application listens on.
   - **SSL for origin**: Enable if your application uses SSL internally.

<Info>
  It's recommended to run one process per container. If running multiple
  processes, ensure they use different ports.
</Info>

5. Click **Add Endpoint**.

### Sticky sessions

Sticky sessions ensure all requests from a client are routed to the same server instance, maintaining session state across requests.

To enable sticky sessions:

1. In the endpoint configuration, select **Sticky Session**.

<Frame>
  ![](/images/docs/81299b7686d70d6ddb86f019bfcfe9ab80f97bc154949c8ac1cfd1dac4563f1f-image.png)
</Frame>

2. Choose an identifier (headers like `X-Forwarded-For` or `User-Agent`, or cookies like `SessionID`).

3. Click **Add Endpoint**.

### Server-Sent Events

A CDN endpoint delivers [Server-Sent Events](/cdn/server-sent-events) without extra configuration, because an event stream is standard HTTP traffic. Your container writes the events, and the edge streams them to the client.

Three points apply to a container that serves an event stream:

- Send `Cache-Control: no-cache` with the stream. A CDN endpoint caches an event stream like any other response, and a container that sends no `Cache-Control` gets the pull zone's default cache time. See [Keep the event stream out of the cache](/cdn/server-sent-events#keep-the-event-stream-out-of-the-cache).
- Send a heartbeat at least every 30 seconds, and flush every event immediately. See [Keep the stream active](/cdn/server-sent-events#keep-the-stream-active).
- A [rolling update](/magic-containers/rolling-updates) or a scale-in closes the streams that the instance holds. Handle `SIGTERM` and close the streams cleanly, as described in [Graceful Shutdown](/magic-containers/graceful-shutdown). The client then reconnects to another instance.
- Enable [sticky sessions](#sticky-sessions) if the stream depends on state that only one instance holds.

The heartbeat is what a CDN endpoint needs, because the edge closes a stream that carries no data. An [Anycast endpoint](#anycast) reaches your container without the edge in the path, so that rule does not apply to it. A CDN endpoint is still the better choice for an event stream in almost every case: it terminates TLS, it puts the connection on the edge network close to the client, and the heartbeat that keeps it open is a few bytes.

## Anycast

Anycast endpoints map your container to an Anycast IP address, routing requests to the nearest node for improved performance.

To create an Anycast endpoint:

1. Go to **Magic Containers** and select your container.

2. Click **Endpoints**, then **Add New Endpoint**.

<Frame>
  ![](/images/docs/08f7158fa6535905e68b635aca2e223d1818ab25753596466e881f51bbea8ee0-image.png)
</Frame>

3. Select **Anycast** as the type.

<Frame>
  ![](/images/docs/471a57e384cb41e7cbf6373ad1352046d6307207e105b0c0fe0b710096023f92-image.png)
</Frame>

4. Configure the endpoint:
   - **Name**: A unique name for this endpoint.
   - **Container Port**: The port your application listens on inside the container.
   - **Exposed Port**: The port available on the Anycast IP.

5. Click **Add Endpoint**.
