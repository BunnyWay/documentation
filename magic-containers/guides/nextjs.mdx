This guide walks you through building and deploying a Next.js application to Magic Containers with GitHub Container Registry. You'll need:

- A GitHub account for source code and container registry

<SignupInfo />

## Create the Next.js app

Create a new Next.js project:

```bash
npx create-next-app@latest app-nextjs
cd app-nextjs
```

### Configure standalone output

Update your `next.config.ts` to enable standalone output mode for Docker:

```typescript next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "standalone",
};

export default nextConfig;
```

### Create an API route

Create a simple API route to test the deployment:

```typescript app/api/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  return NextResponse.json({ message: "Hello from Bunny 🐰" });
}
```

## Run locally

Start the development server:

```bash
npm run dev
```

Visit [http://localhost:3000](http://localhost:3000) in your browser, or test the API route:

```bash
curl http://localhost:3000/api
```

## Create the Dockerfile

```dockerfile Dockerfile
FROM node:22-alpine AS base

FROM base AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci

FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

FROM base AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
RUN if [ -d "/app/public" ]; then cp -r /app/public ./public; fi

ENV PORT=80
EXPOSE 80

CMD ["node", "server.js"]
```

### Pass build-time variables

`next build` inlines `NEXT_PUBLIC_` variables and bakes in anything `next.config.ts` reads, and `docker build` doesn't read your shell's environment. Declare each one as an `ARG` in the `builder` stage, or the build runs without it:

```dockerfile Dockerfile
FROM base AS builder
WORKDIR /app
ARG NEXT_PUBLIC_CDN_URL
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build
```

Pass the value with `docker build --build-arg NEXT_PUBLIC_CDN_URL=https://myapp.b-cdn.net`, or with `build-args` in `docker/build-push-action`.

## Add Optimizer

Your CDN endpoint is already a pull zone in front of the app. Turn on [Bunny Optimizer](/optimizer/dynamic-images/overview) there, and `next/image` resizes images at the edge.

<Steps>
  <Step title="Configure the endpoint's pull zone">
    Open the pull zone that serves your CDN endpoint under **CDN → Pull Zones**. Turn on [URL Query String](/cdn/vary-cache#url-query-string) vary, since endpoint pull zones ignore query strings by default and `?width=1080` would come back as the cached `?width=640` image.

    Enable Optimizer, then turn on the Dynamic Image API and automatic WebP under **Optimizer → Settings**. Next.js already minifies CSS and JavaScript, so turn Optimizer's minification off.
  </Step>
  <Step title="Add the image loader">
    The loader turns each `next/image` width into an Optimizer URL. With `NEXT_PUBLIC_CDN_URL` unset, it returns relative URLs that go through the same pull zone.

    <BunnyLoader />
  </Step>
  <Step title="Point Next.js at the loader">
    ```typescript next.config.ts
    import type { NextConfig } from "next";

    const nextConfig: NextConfig = {
      output: "standalone",
      images: {
        loader: "custom",
        loaderFile: "./lib/bunny-loader.ts",
      },
    };

    export default nextConfig;
    ```

    Rebuild and push the image. [Smart Cache](/cdn/smart-cache) is on for endpoint pull zones, so the edge skips HTML and deploys need no purge.
  </Step>
</Steps>

To put a pull zone in front of Next.js on another host, see [Serve Next.js from Bunny CDN](/cdn/integrations/frameworks/nextjs).

## Connect a database

You can connect your app to [Bunny Database](/database) directly from the dashboard:

1. Go to **Database > [Your Database] > Access**
2. Click **Generate Tokens**
3. Click **Add Secrets to Magic Container App**
4. Select your app

The `BUNNY_DATABASE_URL` and `BUNNY_DATABASE_AUTH_TOKEN` environment variables are now available in your app:

```typescript app/api/users/route.ts
import { NextResponse } from "next/server";
import { createClient } from "@libsql/client/web";

const client = createClient({
  url: process.env.BUNNY_DATABASE_URL!,
  authToken: process.env.BUNNY_DATABASE_AUTH_TOKEN!,
});

export async function GET() {
  const result = await client.execute("SELECT * FROM users");

  return NextResponse.json(result.rows);
}
```

See the [TypeScript SDK documentation](/database/connect/typescript) for more details.
